How it works · how to use it

Agent HTML,
on every machine you own.

Shelf is a local-first store for HTML written by agents: one CLI, a desktop app that reads your disk, and a PWA for your phone.

TyrellD1/shelf · v0.1.0

The problem

A finished report should not die in a temp folder.

Agents write good HTML — explainers, decks, review checklists — and then the file sits in one project directory on one machine.

Shape

One writer, one store, three ways to read it.

Solid = the write path · dashed = the read paths

The write path

Write once; the shelf handles the rest.

read bytes
sha256
store in ~/.shelf
push row
synced

The push is the only networked step, and a failure there never loses the file: it stays local and is pushed by the next shelf sync.

What to call

One command at the end of a task.

$ shelf write ./outputs/q3-report.html --json
{
  "ok": true,
  "action": "created",
  "path": "outputs/q3-report.html",
  "file": {
    "id": "sf_a41c9f0b7d3e28a5c6b1",
    "machineId": "tys-macbook-pro",
    "bytes": 48213
  },
  "pushed": true
}

Or write and look

shelf open <path> writes the file if it is not on the shelf yet, then brings the desktop app forward on that document.

Agents only ever need these two calls. The html, slides and review-checklist skills end by telling the agent to run one of them.

Real output shape · ids are derived, not random

Use

Eight commands, one story.

CommandWhat it does
shelf setupBrowser handoff, stores a long-lived key, sets this machine's id
shelf write <path>Store and push a file; existing paths become -v2, -v3, …
shelf open <path>Write if needed, then open it in the desktop app
shelf listNewest first, searchable and filterable by machine
shelf syncPush local writes, pull what the other machines wrote
shelf statusAccount, machine id, counts, pending pushes, last sync

Every command takes --json; add --stream for progress lines before the result.

First run, once per machine

Authorize in the browser; never think about it again.

1

Install

curl … install.sh | bash drops the CLI in ~/.local/bin.

2

Authorize

shelf setup opens the web app; you click once and the key lands on a loopback port.

3

Name the machine

It prompts for a machine id (defaulting to your hostname). That id colours every row you write.

After that: all calls are authenticated and attributed to that machine id.

The key never expires; shelf logout drops it locally, running setup again rotates it.

Reading it back

Same shelf, whichever screen is nearest.

Desktop (macOS)

Native window, local-first. Documents come off your disk with a strict content policy — fast, and offline. ⌘P searches everything.

Phone (PWA)

Add the web app to your home screen. The same UI, reading the same API over the network.

Terminal

shelf list and shelf read for the agent, a script, or a quick look.

The list is newest-first with a search box, machine filter chips, and a colour per machine.

Everyday cases

The behaviour you should expect without reading the code.

You doShelf does
Write the same path with new contentCreates report-v2.html; the old version stays readable
Write identical bytes againNo-op — nothing uploaded, nothing duplicated
Write offlineStores locally, reports a warning, pushes on the next sync
Sync on a second machinePulls the other machine's files into ~/.shelf/html/<machine>/…

There is no delete by design: paths are immutable and cheap, so a shelf only grows.
